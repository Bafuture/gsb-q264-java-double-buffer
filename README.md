## 任务提示词

以下为本题完整的 User Prompt 原文，两次执行必须使用完全相同的文本。

我们的数据一面写一面被读，直接共享会在读取过程中被改，用锁又影响吞吐。请从零实现一个双缓冲（乒乓缓冲）切换组件。仓库目前只有一个空的 Maven 工程（pom.xml 只声明 JUnit 5 与 AssertJ）。要求：1) 维护两个缓冲区，写者只写其中一个，读者读另一个，通过原子引用切换；2) 支持切换语义：切换后新数据立即可读，已经在读旧缓冲的线程完成后再回收旧缓冲；3) 支持旧缓冲复用：可配置保留几代缓冲，超出的需要等待没有读者后再复用；4) 正确性：读取过程中不得读到被写入一半的缓冲，需有测试证明；5) 支持批量写入：写入在本地缓冲完成后一次性提交，避免频繁切换；6) 支持统计：切换次数、被延迟回收的次数与当前活跃读者数；7) 说明与读写锁方案的取舍（内存换吞吐），并给出两者在读写比不同时的耗时对比；8) 测试覆盖写读隔离、切换即时生效、旧缓冲回收等待、批量提交、并发一致性与性能对比；`mvn -q verify` 一条命令跑通。

## 提交要求

3. 完成后在所属分支（A 或 B）上提交，产物快照的父提交必须是初始环境快照。
